## Implemented contract

- `domain.ts` validates a real Monday KST date, creates R1–R7 through Sunday and fixes qualifying at 20:00 KST (11:00 UTC), main at 21:00 KST (12:00 UTC). Races keep original scheduled anchors even when processing is late. A weekly key, unique day slots, season/round keys and atomic D1 batches prevent duplicate scheduling.
- Regular creation validates then seals in one command. No editable draft administration is introduced. The original eight engine IDs r1–r8 are stable identities, with immutable season profile snapshots and slot mappings; this first adapter intentionally rejects other rosters instead of silently mapping them to a different engine racer. Racer/profile editing and custom seasons remain Phase 3-B.
- The manifest freezes roster, schedule, engine/source/config/track hashes, laps (1–30), current points revision and generation policy. The Drizzle schema and companion SQL are under `db/racing-phase3a/`, outside the production schema/journal. SQL enforces identity, immutable seed inputs/results/audits, valid classifications, transitions and transaction assertions. Existing migrations and backup v1–v12 are untouched.
- `engine.ts` separates v0.14 qualifying from main generation. Qualifying entropy is independent of main entropy. Passing the same historical seed to both stages reproduces the old complete meeting exactly; existing monolithic adapters retain their behavior. `historical.ts` dispatches v0.1–v0.14 without falling forward to the newest engine. The shared v6/v10 changes only add optional already-qualified input; historical callers use the old default path.
- Each race/stage gets a random 256-bit secret at seal. AES-GCM encrypts it using an externally supplied private key and binds ciphertext to its input hash. A SHA-256 commitment binds the secret/input. The deterministic external contribution reference is fixed at seal; its digest becomes immutable before simulation. Retries cannot change the contribution or use a new secret. Missing entropy fails closed. The `isolated-external-v1` port is a **synthetic test contract**, not a selected production beacon or proof against a privileged operator.
- Strict scheduled-start policy: qualifying generation cannot begin before 20:00, main before 21:00. Qualifying that was never generated before main time is an incident, not a fabricated grid. This choice requires a measured live buffer before Phase 3-C can broadcast on time. No after-close pre-generation policy is silently enabled.
- Encrypted private artifacts carry the stage contract, source/config identity, input hash, qualifying hash and immutable value. D1 stores commitments, object hashes, leases and the small official classification, not full replay frames. Store writes are read back and verified before committing a pointer. No public artifact, replay, admin or live API is installed.
- Generation uses owner-token leases, same-input retry, a frozen candidate hash and conditional completion. Timeout recovery may recompute the same committed inputs. Differing candidate hashes quarantine the race; lost responses recover committed hashes; stale workers cannot commit; cancellation during object upload prevents completion. Failed writes leave only unreferenced encrypted objects. Production orphan collection is deferred.
- Main race states: SEALED → GENERATING → READY → RUNNING → PROVISIONAL → FINAL. Generation failures remain in the stage's FAILED state and preserve all inputs. The scheduler reconciles multiple overdue transitions from persisted timestamps; repeated calls return existing state. FINAL data cannot be cancelled, updated or deleted. Incident cancellation requires a reason and expected revision before READY. Advanced incident/dispute workflows are deferred.
- Roles are internal **server capability ports** (`scheduler`, `generator`, `incident`); viewers are rejected before writes. Callers must never construct these ports from request bodies. Authenticated HTTP/session/Origin/CSRF adapters and operator screens belong to Phase 3-B. There is no publicly callable command route in this change.

## Remaining release gates

1. Review/merge the source separately; no main merge or deployment is part of this work.
2. Supply the production entropy source/round verification and independent commitment witness; approve key custody, private object store, backup/restore manifest and hash verification at runner deployment. The frozen source manifest is verified by tests/CI; a production runner needs an attested build boundary.
3. Reconcile actual installed schema and private originals before assigning an operational migration number. Extend backups additively only alongside an approved deployment schema. Current production exporter deliberately does not back up isolated Racing tables.
4. Build Phase 3-B authenticated commands and audit user identity, profile revisions, custom seasons and operations recovery. The internal audit currently records service role, operation, race identity and timestamp.
5. Phase 3-C: runner capacity and deadline/buffer measurements, real scheduler ownership, no-future-data projection, release/cache security and multi-client broadcast. A complete encrypted private replay is not a live API.
6. Phase 3-D: prediction/settlement/Credit contracts and exact refund capacity, separate approvals. No Wallet/Ledger/AI code is changed here.

No live D1, migration, Production, Wallet, Ledger, AI, betting, sponsorship, streaming or infrastructure mutation was performed. Passing isolated tests establishes the foundation's local contracts, not live operational readiness.
