## 버전별 봉인·복원 계약

서버 전용 RACING_KEYRING Secret은 active (버전 ID)와 keys (ID별 32바이트 AES 키의 소문자 hex) 필드를 가진 JSON이다. ID는 영숫자·밑줄·하이픈 1~48자다. 관리자는 한 번 사용한 버전에 다른 키를 배정하지 않는다. 새 secret_cipher와 R2 객체는 v1:ID:IV:ciphertext 형식이다. 포맷 버전과 ID 접두사, 기존 input/output hash를 함께 AES-GCM AAD로 인증한다. 출력 hash와 기존 DB 스키마를 유지한다.

버전 없는 기존 데이터는 지정된 legacy Secret RACING_SEAL_KEY로 연다. keyring이 없는 기존 환경은 원래 쓰기 형식을 지원한다. keyring이 구성된 환경의 새 쓰기는 active 버전을 사용한다. 버전 식별자가 없어진 과거 키, 잘못된 키, 잘못된 AAD나 envelope는 공개 read에서 일반 503을 반환한다. 공개된 적 있는 기록도 자격 구성 변경 후에는 평문 캐시를 재사용할 수 없다. 공개 HTML·JS에 keyring을 넣지 않는다.

|권한|격리 환경에서 필요한 범위|
|---|---|
|봉인 운영자/주간 scheduler|운영자 인증과 D1 권한, active 암호화 키. 과거 키를 전달할 필요가 없다.|
|생성 Worker|전용 D1·R2, 과거 봉인 입력 복호화 및 active 버전 암호화, 읽기 전용 서명 기여값과 검증 공개키|
|사설 reader|전용 D1/R2 읽기, 지원하는 버전들의 복호화 키, 외부 공개 경로 없음|
|프런트 Worker|reader 서비스 바인딩. 키와 원본 저장소 접근 권한 없음|
|엔트로피 서명자·키 복원 담당자|서명 개인키는 독립 공급자에 보관. 봉인 키 백업은 저장소 백업과 분리하고 복원 권한과 감사를 지정.|

교체 순서는 새 버전 등록 → 읽기·생성 역할에 과거 및 새 버전 배포 → 격리 canary에서 읽기 검증 → 새 active로 쓰기 전환이다. 이전 버전으로 쓰기를 되돌릴 때에도 이미 생성한 신규 버전의 복호화 키와 버전 envelope를 이해하는 바이너리를 보존한다. 3-E 바이너리는 새 형식을 읽을 수 없다. 필요한 키의 보존 기간은 결과 객체뿐 아니라 미생성 경기의 D1 secret_cipher와 보존 백업까지 포함한다. 키 유출 대응 및 재암호화는 별도의 승인 작업이다.

격리 복원 명령은 `node --import ./scripts/sites-env.mjs scripts/test-racing-phase3f-restore.mjs`이다. 테스트는 legacy 시즌, A로 봉인된 추가 시즌, A 예선 및 B 본경기를 만든다. Miniflare를 정지하고 D1·R2 저장 디렉터리를 새 루트로 복사한 뒤 새 인스턴스에 키를 별도로 주입한다. 복원 전후 공식 응답과 예선 다시보기를 비교하고 다음 시즌의 봉인 입력으로 생성을 재개한다. 과거 키 제거, 다른 키 값, legacy 키 제거, 같은 키 값에서 ID 변조, AAD 변조, 잘못된 설정, FK 검사를 포함한다. 이 시험은 로컬 Miniflare 저장 형식에 대한 것이다. 클라우드 백업 형식, 실제 키 에스크로, KV/공급자 복구는 별도 게이트다.

## 12월 3일 스테이징 승인 요청

조회 가능한 Sites에서 owner 목록은 holocron-korea, editor 목록은 비어 있었다. 저장소 manifest는 기존 프로젝트의 DB와 R2 null을 선언한다. 독립 자원의 식별자·권한을 확인할 수 없어 실제 리허설은 BLOCKED다. 아래 값은 **승인 요청안**이다.

1. 환경 소유자가 별도 프로젝트·호스트, D1/R2/KV 및 reader/runner 서비스 ID, 접근 담당자, 배포할 SHA, UTC/KST 운영 시간, 비용 한도, 모니터링 권한을 지정한다. 운영 리소스와 ID가 겹치면 중단한다. 배포·Cron 설치/철회·부하 발생을 각각 승인받는다.
2. 승인된 운영자가 스테이징에만 설치한다. 접근 제한한 프런트→사설 reader, generator→격리 D1/R2 및 읽기 전용 KV를 확인한다. 합의한 별도 공급자의 서명 라운드·불변 기여값·장애 정책, 테스트 키 버전 복원을 점검하고 신호가 누락되면 공개를 보류한다. 공식 공급원 지정 및 실제 서명자 독립성은 미확인이다.
3. 20:00 예선·20:58 프리쇼·21:00 생성, 두 CDN 지역의 API/HTML/RSC/prefetch/오류 응답과 캐시 상태, FINAL 경계, 워커의 실제 CPU·메모리·지연을 수집한다. 신규 및 재접속 각각 **1→16→64 이하**(실제 승인 상한 우선), 단계당 2분. 누출·시계 역행·결과 불일치·잘못된 리소스 접근은 즉시 중단한다. 5xx가 30초간 1% 초과하거나 제공자 자원 한도 경보가 발생하면 부하를 중단한다. 이는 제안한 중단선이며 출시 SLO는 별도 합의한다.
4. 중단 시 테스트 부하와 스테이징 Cron을 끄고 공개 바인딩을 차단한다. 쓰기 동결 후 D1·R2·KV 일치 시점, 키 버전 목록 및 객체 해시를 보존한다. 승인된 형식 호환 버전으로 롤백한 뒤 격리 사본에서 공식 순위·봉인 입력·무결성과 복호화를 확인한다. 비밀값을 보고서/로그에 남기지 않는다.
5. Windows/Linux CI는 SwiftShader이고 모바일은 viewport다. 실제 GPU·모바일, 관리형 CDN/Cron/Worker, 키 보관자 복구 리허설은 BLOCKED다. Production D1 설치 Journal, 최신 전체 백업·Wallet/Ledger·제약조건 복원은 독립 감사 게이트로 유지한다. 12월 4일 승인권자가 증빙을 검토한다.
