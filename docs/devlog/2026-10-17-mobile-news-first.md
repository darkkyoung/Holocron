## Implementation

At 550px and below, the News hero remains an accessible heading but is visually collapsed, the large archive banner no longer takes first-screen space, and the feedback entry follows the story area. The desktop hero, source rail, feedback rail, filters and cards remain in the same DOM and retain their desktop styles. The mobile section heading and gaps are compact, leaving the first story directly after the two-row public navigation. The card representation, grouping, retrieval order and pagination policy did not change.

One existing `GuestCreditStatus` instance remains under the common Header. Mobile CSS positions its summary as an outlined balance badge alongside the brand, with room for the News search icon. Its disclosure reveals the same attendance, Guest cap, Google action, rewards/errors and refresh controls. The only balance input remains the server response from the existing visit flow; loading/errors never render zero. No new Credit client or visit listener was added. A disclosure open/close only changes native display state. Desktop retains the earlier Credit placement. Admin routes do not render this public status.

The News-only mobile search trigger and existing explorer share a small React context for *presentation openness only*. The query, category, Work ID, filtering, URL `?work=` handling and page reset stay in the original explorer. The single filter form stays mounted when closed, so its state survives reopening and viewport changes. Active filters have a compact visible status and reset action. The panel is a disclosure-like inline area, not a modal; it needs no backdrop/body scroll lock. The trigger exposes `aria-expanded`/`aria-controls`; opening focuses the native search input, and the in-panel result button closes it and returns to the list. Leaving the mobile breakpoint closes presentation only, preserving filters. All links remain normal anchors.
