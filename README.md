# HOLOCRON
Korean Star Wars news archive. Vinext + Cloudflare Worker + D1.

## Operations
The initial deployment is owner-private. Configure the server-only `HOLOCRON_ADMIN_USERNAME`, `HOLOCRON_ADMIN_PASSWORD`, and `HOLOCRON_ADMIN_SESSION_SECRET` values, then open `/admin/login`. Login is verified server-side and management pages and APIs require the signed, HttpOnly administrator session cookie. Missing configuration fails closed. Legacy `settings.admin`, `admin_identity_v2`, and ChatGPT identity rows are not authorization inputs.

Collection can be initiated from the admin screen or by the hosted GitHub Actions schedule. Both entry points use the same collection-run service and the same seven-source pipeline; concurrent runs are prevented by an atomic, expiring D1 lease. The pipeline uses the StarWars.com news index, five public RSS feeds, and the Forbes news sitemap through explicit adapters. Each source and article is isolated, normalized URLs are skipped incrementally, and only the first 12 new candidates per source are processed in one run; remaining candidates are reported and picked up by later runs. No access restriction bypass or paid content extraction is attempted.

StarWars.com and Star Wars News Net are trusted franchise sources. Collider, The Hollywood Reporter, Deadline, Variety, and Forbes must explicitly mention Star Wars in feed or page metadata. Articles older than 90 days are dropped. Review and Character Spotlight content is placed in the recoverable review queue before AI processing, as are missing or ambiguous publication dates, metadata failures, invalid Korean AI output, and unavailable OpenAI processing. A one-time, override-safe maintenance pass also moves legacy published editorial items to review, but never changes an explicit administrator publish decision. It runs on the first authorized administrator-state load as well as collection, then records a completion marker. Source-level counters and failures are stored in `last_collection`; source markup can still change and require adapter maintenance.

Configure `OPENAI_API_KEY` as a hosted secret via the OpenAI Developers plugin; optional `OPENAI_MODEL` defaults to `gpt-4.1-mini`. Scheduled collection additionally requires the same strong `HOLOCRON_SCHEDULER_SECRET` value in the Sites production environment and the GitHub Actions repository secret. The scheduled endpoint accepts only authenticated `POST` requests, fails closed when the server secret is absent, and never reuses administrator credentials. Never place keys in the client or repository. The initial six articles are manually researched Korean summaries, not API-generated. Runtime AI uses only available article metadata, returns bounded Korean summaries, and matches an existing topic only for the same event. It does not summarize a full article when only metadata is available.

Optional Works metadata import uses the server-only `TMDB_API_READ_ACCESS_TOKEN` (TMDB v4 API Read Access Token). It is used only from the session-protected `/admin/works` importer to search and prefill a draft; `/works` always renders from D1 and never calls TMDB. The administrator reviews every draft before saving it, and there is no automatic TMDB sync. Do not place the token in source, browser code, or logs.

Topic merging/splitting and exclusions persist in D1. Automatic processing never overwrites `topic_override` or `status_override`. The earliest known timestamp in a topic is its representative; full timestamps are normalized to UTC, while date-only values remain date-only because their time is unknown. Franchise is stored separately (`star-wars`) for future expansion; no other franchise feed is active.

Initial SWNN card uses an explicitly labeled related official Ahsoka image because the source page's own image metadata could not be retrieved. Article/image copyright remains with the original publishers.

Canonical-only foundation adds conditional D1 admission + existing Credit debit in one transaction, keyed abuse limits, leases, request replay protection, conservative injected cost profiles and idempotent full-refund settlement. New additive `0017_assistant_admissions.sql` and backup v5 preserve the same 14 durable datasets and historical v1–v4. No provider, generate endpoint, UI activation or deployment. Retrieval additionally requires dedicated `HOLOCRON_ASSISTANT_ABUSE_SECRET` and trusted Cloudflare edge identity; no real secret was provisioned. Flag stays false and **COMING SOON** remains.

**9D-B.1 acceptance remains BLOCKED:** the approved initial policy now restricts all AI spending to Accounts, enforced both by the service and the atomic D1 admission/debit boundary. Guests retain rewards and free retrieval; Guest Q&A is deferred. Ordinary Account failures refund exactly once when the protected wallet can accept the full refund, but a valid intervening reward or Guest migration can exhaust Account numeric headroom at `MAX_SAFE_INTEGER`. Such obligations remain `refund_pending`, without partial refunds or relaxed Credit rules. Terminal records are eligible for lazy cleanup at 48 hours; unresolved obligations are never deleted just because they expired. Run `pnpm test:assistant-admission` and `pnpm test:assistant-refund-safety`; see [refund safety, retention and remaining blocker](docs/devlog/2026-10-16-assistant-refund-safety.md). 0017/v5 are unchanged; no deployment, AI activation or 9D-C work.

Competing credits cannot take that capacity; a full correlated refund consumes its own reservation. No migration/backup change. The new runtime requires the existing canonical **0017** schema before any Credit writes; missing schema fails closed. **Overall 9D-B remains BLOCKED** by the reward-entitlement decision: rejection consumes no claim and same-window retry is safe, but a later KST day/week or unpublished Quiz cannot recover the original reward under existing rules.
