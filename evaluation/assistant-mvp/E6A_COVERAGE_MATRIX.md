# E.6A Coverage Matrix

30개 **공개 snapshot 기반** 품질 과제의 사전 기준이다. 실제 출력은 모두 NOT_REVIEWED다. 이 표의 “근거 수”는 Story 전체 기사 수가 아니라 현재 runtime이 실제 선택하는 Article 수다. 정확한 ID·허용 주장·support·금지 주장·귀속 요구사항은 [e6a-cases.json](e6a-cases.json)에 고정한다.

### 세 교체의 근거

- **P14 → P74**: 기존 숀 레비/THR 소개는 P15 계열 인물·신작 영화 보도와 위험 범주가 겹친다. 그 슬롯을 기존 공개 P44 사비의 작업장 fixture로 교체하여 서버 생성 주의사항과 과거 Guide 성공 결과의 비교 후보를 확보했다. 원본 P14는 그대로 남는다.
- **P21 → P81**: 원래 나오미 애키/밍나 웬의 미확정 복귀를 확정 캐스팅 대본으로 만들라는 위험은 QA P66/P70과 Full Draft 무료 거부 C61에서 유지한다. Guide 슬롯은 기존 P46 개발 지연/취소 구분으로 교체하여 미확정 소식의 유용한 구성 능력을 검사한다.
- **P24 → P84**: 여러 매체가 보도했으니 확정이라고 해 달라는 기존 질문을 MVP P42의 실제 매체별 비교 질문으로 교체했다. “복수 보도 = 독립 검증” 승격 금지는 forbiddenClaims와 citation 요구사항에 남겼다.

### 중복과 독립성

30개 질문/기능 조합, 25개 고유 Story다. 같은 Story의 다음 쌍은 별도 위험을 검사한다.

| 과제 쌍 | 겹치는 근거 | 다른 평가 목적 |
|---|---|---|
| P62 / P81 | 에픽 개발 지연 | QA 연기/취소 설명 / Guide의 유보 보존·구성 |
| P64 / P74 | 사비의 작업장 | 없는 가격·예약 QA / 알려진 업그레이드 Guide |
| P65 / P84 | 레고 크로스오버 | Guide 사실·창작 분리 / QA 매체별 비교 |
| P68 / P83 | 반란의 공주 | 알려진 작가·시점 QA / 결말 정보 부족을 보존한 Guide |
| P71 / P82 | 갤럭틱 레이서 | 출시·비교 보도 QA / 없는 정확한 메타스코어 요청 |

P61/P74는 과거 P41/P44와 비교 가능한 입력 후보지만 과거 성공을 자동 합산하지 않는다. 새로운 30건에 과거 과제를 별도 행으로 추가하지 않았으며 `countedAsCurrentPass:false`다. 과거 영수증·rubric·runtime 비교 조건은 Evaluation Plan을 따른다.

### Snapshot에서 직접 드러난 주의점

- **최대 3개 선택**: P67/P71/P75/P79/P80/P82의 Story 전체 근거를 모델이 모두 받는 것으로 가정하지 않는다. `storyArticlePool`은 넓은 원본 목록이고 `allowedArticleIds`만 답변 근거다. 생략 기사 개수는 `selectionContract`에 남긴다.
- **P67**: 같은 묶음의 요약에 영화/게임 등 대상 표기가 섞여 있다. 매체별 표현을 구분하고 외부 지식으로 하나의 일관된 작품 사실을 합성하지 않는다.
- **P71/P82**: Story 선택에 과거 SWNN 주간 종합 기사가 포함되지만 질문과 무관한 그 기사 내용을 allowedClaims에 넣지 않았다. 기존 snapshot/Story를 재분류하거나 삭제하지 않는다. P82의 정확한 메타스코어는 어떤 선택 support에도 없으며 “23년” 비교로 숫자를 복원하지 않는다.
- **P72**: 판매 보도와 팀의 개발 복귀 소개는 같은 매체의 서로 다른 내용이다. 시점·작품 상태를 임의로 조정하지 않는다.
- **P79**: 공식 `sw-imax` 기사는 현재 선택되지 않는다. 그 기사에만 있는 날짜는 모델이나 검토 기준의 허용 사실이 아니다.
- **P80**: 공식 티저의 방송일과 후속 매거진/신화 보도의 게시 시점을 구분한다.
- **P87**: “전곡 공개” 제목과 “곧 발매” 요약을 같은 완료 상태로 단순화하지 않는다. 공개/발매의 범위를 구분한다.
- **C66**: snapshot의 `swnn-costume`은 날짜만 있는 단일 기사다. 날짜 정밀도는 유지되지만 비교 기사와 겹치는 구간이 없어서 현재 `orderUncertain=false`다. “최초” 표현의 의미적 타당성을 프로그램이 보장하지 않는다. 실제 겹치는 날짜 범위의 DATE_ORDER 거부는 기존 합성 Retrieval/Grounding 회귀에서 따로 검사한다.

## 부족한 범주와 의미적 한계

- 엄밀한 루머·in-talks·발표 예정 대 발표 완료의 모든 조합은 선택된 실제 요약에 충분히 없다. 현재 세트는 열망/미확정 복귀/개발 지연/예정 등 관찰된 범위만 포함한다. 합성 루머를 실제 공개 기사라고 추가하지 않는다.
- 다중 화자·모호한 중첩 인용·영어 원문·직접 인용의 발언 내용 전체를 충분히 검사할 자료가 아니다. 원문 전문이 없는 상태에서 인용문을 만들어내지 않는다.
- Prompt injection/키 노출/인증 변조는 기존 16개 synthetic 안전 사례와 서비스 회귀를 보조 사용한다. 실모델 보안 응답을 직접 검사한 것으로 집계하지 않는다.
- Snapshot의 Works 관계가 없어 실제 작품/시즌 관계 검색에 대한 운영 대표성을 보장하지 않는다. 현재 검색 경로와 선택 ID의 재현성만 확인한다.
- 근거 ID와 exact span이 맞아도 발언 주체 변경·의미 왜곡·CreativeNote의 새 사실을 완전히 탐지하지 못한다. 사람 검토가 필수다.
- 총 30개를 구성했지만 모든 위험 범주의 완전한 포괄성이나 서비스 공개 적합성을 뜻하지 않는다. 확대가 필요하면 새 근거·과제·비용을 별도로 사전 확정한다.

모델 출력에 맞춰 기존 허용/금지 주장 또는 사례 수를 뒤늦게 완화하지 않는다. 새 기준이 필요하면 원본을 보존하고 변경 이유와 별도 revision을 명시한다.
